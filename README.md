# Alice

NixOS configuration for the Alice gallery kiosk — a ThinkCentre running GNOME that broadcasts its
own WiFi network and serves a digital collection to visitors at `http://alice`. Managed day to day
by a non-technical attendant through a handful of named commands.

- **Full documentation and install walkthrough:** [`docs/alice.md`](docs/alice.md)
- **Design specs:** [`docs/superpowers/specs/`](docs/superpowers/specs/)
- **Collection software:** [memex2](https://github.com/nimdaghlian/memex2) — a separate repo, cloned
  onto the machine rather than packaged into the flake (reasoning in `docs/alice.md`)

Most of the system is declarative and identical across units. This README covers the exception:
everything that has to be set by hand for each physical machine.

---

## How the pieces fit

Worth understanding before the checklist, because the paths below only make sense with it:

```
/home/gallery/memex2   memex2 checkout — SOURCE only (Markdown Records, templates)
/srv/library           media library, its own disk  → nginx serves at /library/
/srv/www/alice         Eleventy builds directly here → nginx serves at /
```

One web server. Eleventy runs `--watch` as a builder with no server of its own, writing straight into
the directory nginx serves, so there is no copy step. The media library is never copied at all —
nginx reads it in place from its own disk.

Two consequences that are easy to trip over:

- **Alice always uses memex2's external library mode.** Embedded mode would copy the entire library
  into the build output on every rebuild, and Eleventy refuses a passthrough source outside the
  project directory anyway — so a library on a separate disk cannot work any other way.
- **Nothing nginx serves may live under `/home`.** NixOS sets `ProtectHome` on nginx's systemd unit,
  which makes `/home` appear empty to the service regardless of file permissions. That is why the
  build output goes to `/srv/www/alice` rather than the checkout's `_site`.

## Per-machine configuration

Ten things differ per unit. Four are committed to this repo; six exist only on the machine.

| # | What | Where | Required |
|---|---|---|---|
| 1 | Hardware config | `nixos/hosts/alice-N/hardware-configuration.nix` | yes |
| 2 | Flake entry | `nixos/flake.nix` | yes, for a new unit |
| 3 | Preference overrides | `nixos/hosts/alice-N/config.nix` | only if this unit differs |
| 4 | WiFi interface name | `nixos/hosts/alice-N/config.nix` or the host config | only if not `wlan0` |
| 5 | Library disk | partitioned and mounted at `/srv/library` | yes |
| 6 | WiFi SSID + password | `/etc/alice/wifi-credentials` | yes |
| 7 | Attendant password | set with `passwd gallery` | yes |
| 8 | memex2 checkout | `~/memex2` + its `memex.config.yml` | yes |
| 9 | Config repo clone | `/etc/nixos` | yes, for `update-system` |
| 10 | Printed join QR code | generated by `wifi-qr` | yes |

### In this repo (committed)

**1. Hardware config** — generated during install, never written by hand:

```bash
nixos-generate-config --root /mnt
cp /mnt/etc/nixos/hardware-configuration.nix nixos/hosts/alice-1/hardware-configuration.nix
```

Contains disk UUIDs, filesystem layout, and kernel modules for that specific machine. Committed so
each unit's profile is preserved. **The version in `hosts/alice-1/` is currently a stub** — a real
one has never been generated, so `nix flake check` cannot succeed until it is.

**2. Flake entry** — for a second or third unit, add a line to `nixos/flake.nix`:

```nix
alice-2 = mkAlice "alice-2";
```

The name must match the directory under `nixos/hosts/`. It also becomes `alice.unit`, which is how
`update-system` knows which configuration to rebuild — every unit shares the hostname `alice`, so
the directory name is the only thing distinguishing them.

**3. Preference overrides** — shared defaults live in `nixos/config.nix`:

```nix
{
  timezone = "America/Los_Angeles";
  locale = "en_US.UTF-8";
  galleryName = "Alice Gallery";
}
```

To change any of these for one unit only, create `nixos/hosts/alice-N/config.nix` containing just
the keys that differ:

```nix
{ timezone = "America/New_York"; galleryName = "East Wing"; }
```

Per-unit values win; anything not mentioned falls back to the shared defaults. These are build-time
values — run `update-system` after changing them.

**4. WiFi interface name** — defaults to `wlan0`, which is correct because
`networking.usePredictableInterfaceNames = false` is set. If a unit's adapter enumerates
differently, check with `ip link` and override:

```nix
{ alice.wifiAp.interface = "wlan1"; }
```

Note this is a NixOS option, not a preference key, so it goes in a module or the host's
`default.nix` — not in the plain-attrset `config.nix` described above.

### On the machine only (never committed)

**5. Library disk** — the media library gets its own disk, mounted at `/srv/library`. Partition and
mount it during install **before** running `nixos-generate-config`, which writes `fileSystems`
entries for whatever is mounted under `/mnt` at that moment — mount it after and you are hand-writing
the entry instead:

```bash
lsblk                                    # confirm the target disk
parted /dev/nvme0n1 -- mklabel gpt
parted /dev/nvme0n1 -- mkpart primary ext4 1MB 100%
mkfs.ext4 -L alice-library /dev/nvme0n1p1
mkdir -p /mnt/srv/library
mount /dev/nvme0n1p1 /mnt/srv/library
```

Ownership is handled declaratively — a tmpfiles rule sets `/srv/library` to the `gallery` user at
boot, so no manual `chown` is needed on a freshly formatted disk.

The path is configurable via `alice.site.libraryPath`, but it must match memex2's `library:` setting
(item 8) or the generated URLs and the files on disk will disagree.

**6. WiFi credentials** — the one secret. Seeded during install from a committed template, then
edited in place:

```bash
# During install the repo is cloned to /tmp/alice and the target system is mounted at /mnt
mkdir -p /mnt/etc/alice
cp /tmp/alice/nixos/hosts/alice/wifi-credentials.example /mnt/etc/alice/wifi-credentials
chmod 600 /mnt/etc/alice/wifi-credentials
$EDITOR /mnt/etc/alice/wifi-credentials
```

```
SSID=AliceGallery
PASSWORD=your-passphrase
```

Read at runtime by `hostapd` (which renders its config from it at service start) and by `wifi-qr`.
Deliberately kept out of both git and the Nix store — the store is world-readable, so passing a
passphrase through a Nix option would leak it. Both consumers fail loudly if the file is missing or
incomplete rather than falling back to placeholder values.

**7. Attendant password** — `gallery` ships with the initial password `password` so GDM is reachable
on first boot. Change it immediately:

```bash
passwd gallery
```

The initial value is stored in plaintext in the world-readable Nix store, so treat it as public
until changed. Changing it does not require a rebuild.

`initialPassword` only applies when the account is **created**. Earlier versions of this config set
no password at all, which produces a disabled login (`!` in `/etc/shadow`) — no password works and
there is no way in as `gallery` to fix it. If that happens, boot the installer USB and use
`nixos-enter --root /mnt` to set it from outside.

**8. memex2 checkout** — the collection software, cloned into the attendant's home:

```bash
git clone https://github.com/nimdaghlian/memex2 ~/memex2
cd ~/memex2 && npm install
cp memex.config.yml.example memex.config.yml
$EDITOR memex.config.yml
```

Four values matter:

```yaml
memexId: alice-1              # unique per unit; identifies this machine in the catalog
libraryMode: external         # Alice is ALWAYS external — see "How the pieces fit"
library: /srv/library         # must match alice.site.libraryPath
libraryUrl: /library/         # must match nginx's location block
```

Only the source lives in this checkout. The build output goes to `/srv/www/alice` (via `--output`),
so nothing here is served directly. The `eleventy` service will not start until `npm install` has
run; `gallery-status` reports this.

**9. Config repo clone** — so `update-system` has something to pull from. `nixos-generate-config`
already wrote to `/etc/nixos` during install, so move it aside first or the clone fails:

```bash
sudo mv /etc/nixos /etc/nixos.orig
sudo git clone https://github.com/nimdaghlian/alice /etc/nixos
```

The path is configurable via `alice.configRepo` if you would rather it live elsewhere.

**10. Printed QR code** — generate after the credentials are set, then print it for the wall:

```bash
wifi-qr      # writes /home/gallery/wifi-qr.png
```

## Attendant commands

Defined in `nixos/modules/aliases.nix`. These are the whole interface for routine work.

| Command | What it does |
|---|---|
| `make-gallery <dir>` | Catalog a directory of media into Records and a Collection |
| `gallery-status` | Plain-English health check of WiFi, site builder, and web server |
| `restart-site` | Restart the site builder if the collection stops updating |
| `update-system` | Pull the latest configuration and rebuild |
| `wifi-qr` | Regenerate the printable WiFi join QR code |

Day-to-day: drop media into `/srv/library/<gallery-name>/`, run
`make-gallery /srv/library/<gallery-name>`, then edit the generated Markdown in Obsidian. The site
rebuilds automatically; refresh the browser to see changes.

## Repo layout

```
nixos/
  flake.nix              # one entry per machine; merges preferences
  config.nix             # shared preferences
  modules/
    settings.nix         # applies preferences; declares alice.unit / alice.configRepo
    wifi-ap.nix          # hostapd + dnsmasq + AP-scoped firewall
    eleventy.nix         # site builder (--watch --output); declares alice.site.*
    nginx.nix            # serves /srv/www/alice at / and /srv/library at /library/
    aliases.nix          # attendant commands
  hosts/
    alice/               # shared across all units
    alice-1/             # per-unit hardware config and overrides
docs/alice.md            # full documentation
docs/superpowers/specs/  # design specs, including deferred work
```

## Status

Not yet installed on hardware. Nothing in `nixos/` has been evaluated by Nix — the development
machine has no Nix installed — so expect to fix errors during the first `nixos-install`. The live
installer ISO does have Nix, so validate there before installing:

```bash
nix --extra-experimental-features 'nix-command flakes' \
  eval /tmp/alice/nixos#nixosConfigurations.alice-1.config.system.build.toplevel.drvPath
```

See the build-status table in `.claude/skills/alice/SKILL.md` for the current known-risk list.
